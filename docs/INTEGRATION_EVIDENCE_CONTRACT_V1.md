# AVRONE ↔ Great Scale evidence contract (v1)

## Purpose

This additive contract makes a daemon test result portable across the AVRONE,
Great Scale, fusion bridge, swarm runner, and attested-history repositories.
It is deliberately narrower than an authorization or identity protocol.

## Event

```json
{
  "schema": "avrone.greatscale.evidence/v1",
  "source": "avrone-daemon",
  "kind": "greatscale_evidence",
  "run_id": "run-1",
  "check_id": "unit-tests",
  "evidence": {
    "failures": 1, "runs": 100, "p": 0.01, "S": 0.0099,
    "orientation": "mixed", "psi": 0.391866...
  },
  "refs": ["test:unit"],
  "capability_id": null,
  "human_root": null,
  "provenance_depth": 0,
  "digest": "<sha256 of canonical event body>"
}
```

The complete evidence object is generated by `avrone.greatscale.evidence_snapshot`;
the abbreviated values above are illustrative. The digest is SHA-256 over UTF-8
JSON serialized with sorted keys, compact separators, ASCII escaping, and NaN
rejected. The digest detects accidental or unauthorized content changes only
when the expected digest is independently retained; it is not a digital
signature or proof of source identity.

## Great Scale mapping

For observed failures (f) over (N) runs:

[
p=f/N,quad S=p(1-p),quad 4S=4p(1-p),quad
Psi=phi^{-2}+S,quad phi^{-2}approx0.381966.
]

The scalar is orientation-blind: (S(p)=S(1-p)). Therefore the event MUST
retain `orientation` (pass, fail, mixed) as a separate channel. A deterministic
all-fail suite has (S=0), but it is not a successful suite.

Repeated-run detection assumes independent, identically distributed trials:
[
P(\text{detect at least once})=1-(1-p)^N.
]
Correlated failures invalidate that interpretation; callers must not present it
as a confidence guarantee without defending the independence assumption.

## Trust and mitigation rules

1. Evidence is read-only data. It cannot authorize tools, deployments, or secrets.
2. Positive `provenance_depth` requires an explicit `human_root`; model-only
   derivations remain at depth zero.
3. Capability identifiers are references, not proof that a capability is valid.
   Verify them against the capability authority before any side effect.
4. Recompute the evidence from integer counts at ingestion. Reject unknown
   fields, inconsistent summaries, non-finite values, malformed references,
   and digest mismatches.
5. Preserve the original receipt and append corrections; do not rewrite history.
6. Keep the existing `AVRONE_CAPGATE` mode opt-in until deployment-specific
   policies and persistent keys have been configured and tested.
7. `provenance_depth` is an integer in `[0, 4096]`; larger or coerced values are rejected.
8. `digest` must be exactly 64 lowercase hexadecimal characters before constant-time comparison.
9. Identifier fields must be canonical (no leading or trailing whitespace) and must reject Unicode control, bidi/format, and surrogate code points to prevent log and identity spoofing.

## Verification

Run:

```bash
python -m pytest -q tests/test_integration_contract.py
python -m pytest -q
```

The first suite covers deterministic hashing, tampering, malformed counts,
orientation blindness, provenance claims, and oversized references.

## Integration sequence

- AVRONE daemon: emits and validates this event.
- Swarm runner: forwards the event as a job result, retaining run and check IDs.
- Great Scale: recomputes the residual from integer observations; never trusts
  a caller-supplied scalar.
- Capability Authority: independently validates capability and approval state
  before side effects.
- Attested History: stores the canonical event digest in its append-only chain.

No cross-repository runtime connection is claimed by this contract alone.

## Daemon producer: flake_probe

The daemon's flake_probe now emits a v1 evidence event for a baseline-relative
measurement whenever at least two executions completed. Execution 1 is the
reference; it is **not** a comparison trial. For n completed executions:

    m = n - 1,  p = d / m

where d is the number of later executions whose output differs from execution
1. The Great Scale snapshot and portable event therefore use runs = m, not n.
A one-execution probe has zero comparisons: it is marked insufficient_samples,
has no Great Scale snapshot, and emits no evidence event. A finite
baseline-consistent sample is not proof of determinism.

The event check_id identifies the probe invocation; run_id uses the daemon run
identifier when it satisfies the contract, otherwise a fresh opaque identifier.
References identify the allow-listed tool and fixed-first-run measurement model.
Output content is never copied into the event. The SHA-256 digest is a canonical
content-integrity check, **not** a signature, an identity assertion, or
authorization. The 95% detection projection remains conditional on independent
comparison outcomes given the observed baseline; stateful or correlated tool
behavior invalidates that projection.
